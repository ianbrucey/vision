# TalentLynk — Strategic Brief

## 1. Strategic Intent

**Goal:** Build a tech-enabled Management Prime platform — a vendor portal and bid management application that sits on top of the Vision administrative intelligence engine. TalentLynk automates the federal contracting lifecycle: vendor onboarding, solicitation matching, compliant pricing, proposal generation, digital sign-off routing, and post-award payment orchestration.

**Success Verdict:**
- [ ] A vendor can self-onboard via a web portal: enter their UEI, confirm auto-populated SAM.gov data, add pricing and licenses
- [ ] A solicitation package (PDF, ZIP) can be uploaded and automatically classified by NAICS, with SOW extracted
- [ ] The matching engine cross-references a solicitation's NAICS codes against the vendor database and returns a scored, ranked list of matches
- [ ] A pricing estimate is generated by overlaying wage determination data on vendor commercial rates
- [ ] A vendor can review and digitally sign a task-specific teaming agreement for a specific bid
- [ ] The system compiles a multi-volume proposal package: filled government forms + custom technical narrative + past performance
- [ ] Post-award: payment tracking, accelerated sub payment routing, and audit logging function end-to-end
- [ ] Internal team has an admin dashboard; external vendors have a self-service portal scoped to their own data
- [ ] All agreement state changes are audit-logged for FAR compliance
- [ ] The platform operates on the same PostgreSQL database and Python FastAPI backend as Vision

## 6. Architecture Decision (Resolved)

**Decision:** Shared database, shared backend, separate frontend. Monorepo.

**Rationale:**
- Vision already ingests documents, extracts structure, manages cases, produces drafts, and provides agent tools. Building TalentLynk as a separate stack would duplicate the ingestion pipeline, the draft system, and the agent infrastructure.
- Keeping one PostgreSQL database eliminates data sync, consistency, and cross-reference problems. A solicitation ingested by Vision is immediately available to TalentLynk's matching engine without API calls.
- The agent is the orchestrator for both apps. The same MCP tools that serve the Vision chat UI can drive automated bid pipelines.
- Separate Next.js frontends serve different audiences (internal team vs. external vendors) with different UX patterns, auth flows, and navigation — but share the design system and API client.

**Alternative considered and rejected:** Separate repos with API integration. This would create a permanent tax: two databases to manage, data sync problems, duplicate ingestion, two auth systems, two API clients. The integration surface between Vision and TalentLynk is too deep for loose coupling — they share the same documents, cases, drafts, and agent tools.

## 7. MVP Scope

The blueprint has 14 subsystems and 80+ design documents. For the MVP, narrow to the core loop that proves the model:

**Phase 1: The Matching Core (what proves the platform)**
1. Vendor onboarding portal (UEI lookup + profile creation)
2. Solicitation ingestion + classification (Vision's existing ingest pipeline extended with NAICS/SOW extraction)
3. Matching engine (NAICS cross-reference → scored vendor list)
4. Agreement generation (task-specific TA from template + vendor/solicitation data)

**Phase 2: The Proposal Engine**
5. Pricing calculator (wage determination + vendor rates)
6. Proposal compilation (filled forms + technical narrative)
7. Digital signature routing (DocuSign integration)

**Phase 3: Post-Award**
8. Payment tracking + sub routing
9. Audit log
10. Vendor self-service portal (full)

**Phase 1 is the showstopper.** If you can demonstrate: a solicitation drops → the system finds matching vendors → generates a compliant legal agreement → that's a fundable MVP.

## 8. Pre-Mortem

**What could break?**
- SAM.gov API rate limits or downtime during UEI lookup breaks the onboarding flow. Mitigation: async lookup with "we'll notify you when your profile is ready" fallback.
- Vendor adoption: small businesses may resist entering pricing matrices and licenses into a portal. Mitigation: the UEI auto-fill is the hook — they enter one field and see 15+ fields populated. Concierge onboarding for first 20 vendors.
- Matching quality: the algorithm may surface irrelevant vendors, eroding trust. Mitigation: Proposal Manager always makes the final selection. The algorithm recommends, doesn't automate.
- Wage determination data freshness: federal wage rates change. Mitigation: store WD revision numbers; flag bids using outdated WD data.
- Vision's existing tables being extended for TalentLynk could create schema bloat or break existing functionality. Mitigation: use dedicated `talentlynk` schema for net-new tables; extend Vision tables only through nullable columns.

**What assumptions are we making?**
- Vendors are willing to share commercial pricing data in exchange for bid access
- SAM.gov UEI lookup API is reliable and fast enough for real-time onboarding
- Vision's ingestion pipeline handles the document formats federal solicitations come in
- The existing auth system can be extended with roles without architectural changes
- One PostgreSQL database can handle both workloads without performance degradation
- DocuSign integration is straightforward (REST API, webhooks)
- The "Command" design system translates well to a vendor-facing portal

**What do we NOT know yet?**
- Actual solicitation volume (10/month or 100/month?) — drives infrastructure sizing
- Vendor onboarding conversion rate — drives UX investment
- Whether SBA will accept contingent W-2 offer letters as key personnel commitment (legal risk)
- SAM.gov API access requirements (API key? SAM registration? rate limits?)
- Whether federal agencies will accept digitally signed teaming agreements (some still require wet signatures)

## 9. Out of Scope (Explicit)

- **Building the TalentLynk frontend now** — this Brief is architecture and planning. Implementation begins after Approval and full spec phase.
- **Mobile app** — web-only MVP. Mobile-responsive, not native.
- **Joint Venture formation automation** — legal entity creation is lawyer territory. The platform can flag JV opportunities but won't file formation documents.
- **SBA certification application** — the platform tracks certifications but doesn't file applications.
- **Real-time bid notifications** — scheduled SAM.gov polling, not push notifications from the government.
- **Automated submission to SAM.gov** — proposals are compiled by the system but submitted by a human.
- **AR factoring marketplace** — the factoring integration is API hooks for a future partner, not a built-in factoring service.
