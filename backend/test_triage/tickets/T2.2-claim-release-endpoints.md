# T2.2 — Claim / Release Endpoints

**Status:** pending
**Depends on:** T2.1

---

## Goal

Users can claim and release solicitations. Admin can assign to any user.

## Routes

```
POST /api/solicitations/{id}/claim     — claim for current user
POST /api/solicitations/{id}/release   — release (unclaim)
POST /api/solicitations/{id}/assign    — admin assigns to any user
```

### POST /api/solicitations/{id}/claim

- Sets `assignee_id` = current user, `assigned_at` = now
- If already claimed → 409 Conflict `{"detail": "Already claimed by {username}"}`
- Returns updated solicitation

### POST /api/solicitations/{id}/release

- Sets `assignee_id` = NULL, `assigned_at` = NULL
- Only the assignee or admin can release → otherwise 403
- Returns updated solicitation

### POST /api/solicitations/{id}/assign

- Admin only (`require_admin`)
- Body: `{"user_id": "uuid"}`
- Sets `assignee_id` = given user, `assigned_at` = now
- Overwrites any existing assignment
- Returns updated solicitation

### Existing list endpoint (add filter)

Add query param to `GET /api/solicitations`:

```
GET /api/solicitations?assignee=me    — current user's solicitations
GET /api/solicitations?assignee={id}  — admin: specific user's solicitations
```

## Acceptance Criteria

- [ ] User claims an unassigned solicitation → `assignee_id` set, 200 OK
- [ ] User tries to claim an already-claimed solicitation → 409 Conflict with message showing who holds it
- [ ] Assignee releases their own solicitation → fields cleared, 200 OK
- [ ] Non-assignee non-admin tries to release → 403
- [ ] Admin assigns to any user → succeeds, overwrites existing assignment
- [ ] Non-admin tries assign endpoint → 403
- [ ] `GET /api/solicitations?assignee=me` returns only that user's solicitations
