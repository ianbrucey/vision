# T1.1 — Admin User CRUD Endpoints

**Status:** pending
**Depends on:** nothing

---

## Goal

Admin can create, list, update, and disable users via the API. All endpoints require `role=admin`.

## Routes

```
POST   /api/admin/users          — create user
GET    /api/admin/users          — list all users
PATCH  /api/admin/users/{id}     — update user
```

### POST /api/admin/users

```json
// Request
{
  "username": "newuser",
  "password": "securepass",
  "email": "new@example.com",     // optional
  "role": "user"                  // "user" | "admin", default "user"
}

// Response 201
{
  "id": "uuid",
  "username": "newuser",
  "email": "new@example.com",
  "role": "user",
  "is_active": true,
  "created_at": "..."
}
```

### GET /api/admin/users

```json
// Response 200
{
  "users": [
    {
      "id": "uuid",
      "username": "...",
      "email": "...",
      "role": "user",
      "is_active": true,
      "last_login": "...",
      "created_at": "..."
    }
  ]
}
```

### PATCH /api/admin/users/{id}

```json
// Request — all fields optional
{
  "email": "updated@example.com",
  "role": "admin",
  "is_active": false
}

// Response 200 — full updated user object
```

## Acceptance Criteria

- [ ] `POST /api/admin/users` creates a user with hashed password, returns 201
- [ ] Duplicate username returns 409
- [ ] `GET /api/admin/users` returns all users with their roles and active status
- [ ] `PATCH /api/admin/users/{id}` updates email, role, or is_active
- [ ] Non-admin requests return 403
- [ ] Newly created user can log in immediately via `/api/auth/login`
- [ ] Admin cannot delete themselves (soft-disable only — `is_active = false`)
